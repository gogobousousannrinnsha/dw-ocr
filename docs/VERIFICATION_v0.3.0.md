## 訂正・Viewerの証拠の区別

Portable同梱Pythonと実DLLを使い、同一文字の2領域の片方だけのSDK訂正を保存→取り込み→訂正保存→適用→JSONL出力まで確認しました。
元runの移動後も成立し、未編集の選択領域・選択対象外領域、元座標・順序・信頼度・原本・bundleを保持しています。
訂正処理中はPaddle・Pillow・OpenCVを読み込まないことも確認しました。

Viewerは1領域6ケースと複数領域正常1ケースの既存利用者報告を継承しています。今回の配布環境で、複数領域の別名保存済み文書を再取り込みし、指定領域だけの訂正をJSONLで照合しました。Viewerの操作を新たに実施したという意味ではありません。
コピー・削除等の構造・識別エラーはreview_xdw、空白文字の訂正はsave_correctionsが拒否します。
複数領域Viewerの異常操作、白紙型、複数ページ、検索、テンプレートは今回の対象外です。

最初のSDK訂正保存では、一時ファイルが他プロセスで使用中となるWinError 32で確定を拒否しました。既存出力を上書きせず停止し、失敗時ファイルを残して別の新規フォルダーで再実行したところ、SDK・Viewer両ケースが成功しました。保持元のプロセスは特定していません。保護ソフトや保存処理の安全確認は変更していません。
